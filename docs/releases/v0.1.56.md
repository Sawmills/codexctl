# v0.1.56

- Outcome metrics: count terminal relay lane stops by `rate_limited`, `capacity`, `login_required` and `token_refused`. A recovered request does not count as a terminal stop. The account server counts accepted authenticated reports; do not add the relay and server totals together (SAW-13453, #237).
- Billing metrics: count a credit-billing selection only after the client passes consent and placement guards and commits the selection. Explicit selections and automatic selections have separate counters; token probes, declined selections and refreshes do not count. Automatic recovery still excludes usage-based accounts.
- Monitoring: add a daily lane-stop recording rule and a critical alert for automatic billing selections in the last hour. Reporting failures are counted separately and do not fail the launch. Terminal evidence remains bounded to seven days, and terminal failure logs share the existing rate limit.

Rollout: deploy the account server image first, then upgrade and restart relays on v0.1.56 before new managed launches. Upgrade clients too: v0.1.55 clients and relays do not send the new outcome reports. HQ owns the Mac upgrades and relay restarts. Installing this release does not deploy the account server, enable billing, or redeem resets. Live capacity-stop coverage and notification delivery require separate acceptance evidence.
