# v0.1.59

- Account servers emit one structured WARN for each accepted lane-stop report,
  beside the existing counter increment. Reports include reason, HTTP status,
  bounded error code, account alias, route and upstream request ID. Missing
  context stays unknown; credentials and response payloads are excluded
  (SAW-13521, #249).
- Relays send the diagnostic context to the account server. Retry, account
  selection, metric labels and request counting stay unchanged (#249).
- Linux CI, release and server-image builds use Namespace runners (#245).
  The separate macOS CI job is skipped on branch and PR runs; the release
  workflow still builds both macOS architectures (#246).
- Server-image publishing reads the manifest digest from structured JSON,
  fixing publication with the Namespace runner's Buildx version (#248).
- Both staging HA overlays pin the logging server before relay upgrades (#250).

Rollout: upgrade account servers before restarting relays on v0.1.59. Older
servers reject the added report fields with HTTP 400. The staging servers were
upgraded through #250 before this release. Existing launches gain the diagnostic
context at their next planned restart. Installing this release does not restart
a lane or relay. HQ owns the three machine upgrades and relay restart.
