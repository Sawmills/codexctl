# v0.1.61

- Count a server-path capacity stop once as `capacity_unconfirmed` when a matching
  pending overloaded response exists but native completion evidence is unavailable
  at launch close. A later confirmed result cannot count the same stop again;
  unrelated receipts remain excluded (FLT-465, #253).
- Add `codexctl state cap`, a dry-run-first local state report and optional
  maintenance command. Apply mode checkpoints unheld numbered logs/thread-history
  databases and compresses old, closed rollouts with verified restore metadata.
  Both explicit resume and `resume --last` restore indexed archives before Codex
  starts. The reviewed Mac LaunchAgent remains opt-in (FLT-505, #255).
- Automatic account-server launches can resume the same session on another
  eligible included account after confirmed terminal capacity failures. Shared
  account/model evidence applies a five-minute cooldown after three distinct
  overloaded requests within two minutes. Recovery preserves session, working
  directory, model and flags, with at most three moves per session per hour.
  Explicit account pins remain pinned; recovery does not select usage-based
  accounts, approve billing or redeem resets (FLT-525, #256).

Rollout: migrate and pin the account server before upgrading clients or restarting
relays on v0.1.61. Older servers reject `capacity_unconfirmed` and lack the shared
capacity tables. Run the new image's ordinary PostgreSQL migration before serving
traffic, then deploy that image. Staging completed the migration and three-pod
image rollout through #257 before this release.

Installing the release does not restart a lane or relay, or install the state-cap
LaunchAgent. HQ owns machine upgrades and the relay restart. The guide requires
the LaunchAgent notice before installation; FLT-505's 24-hour disk watch remains
part of live acceptance.
