# v0.1.62

- `codexctl-central run` defaults to `gpt-6.2-sol` when `--model` is omitted.
  The relay counts `gpt-6.2-sol` for capacity accounting and evidence.
  `gpt-6.1-sol` stays in the allowlist so stored evidence rows keep their
  model attribution (FLT-1614, #264).
- Dependency updates clear the OSV Scanner findings: `rustls-webpki` 0.103.16,
  `webpki-roots` 1.0.10, `openidconnect` 4.1, `rusqlite` 0.41 (patched
  `crypto-bigint` 0.7.11 and `libsqlite3-sys` 0.39.1). One documented exception
  covers the Chrono maintenance notice. The older `RUSTSEC-2023-0071` exception for
  `openidconnect` predates this release and stays (SAW-13160, #261; FLT-1614, #265).
- Staging account-server manifests start and scrape without the retired metrics
  credential file. The pinned image already serves anonymous metrics (SAW-13160,
  #259, #260).
- README simplified and obsolete files removed (FLT-544, #262). Test fixture
  backfill clock fixed (SAW-13160, #263).

Rollout: server first. A v0.1.62 centrally managed client sends `gpt-6.2-sol` to
`/v1/capacity/plan`, and a v0.1.61 account server rejects that model with HTTP 400
`invalid_capacity_plan`, so the launch fails. Pin and roll out an account-server
image built from v0.1.62 source before any client or relay upgrades to v0.1.62.
No database migration is needed. Installing the release does not restart a lane
or relay. HQ owns machine upgrades and any relay restart.
