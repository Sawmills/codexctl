# v0.1.52

- Client: nested plain Codex processes under a pinned lane use that lane's account, preserving the pin across host account switches and fixing nested token-helper 401s (SAW-12569, #199).
- Server: retry transient native errors, bound foreground waits and child settlement, and recover billing checks after repeated native failures (SAW-12986, #193).
- Monitoring: count ended refresh sessions as rejected grants and include per-account refresh and owner-unavailable alert rules in the staging HA overlay (SAW-12651, #198).
- Canary: add an opt-in no-init token path restricted to the canary PostgreSQL database; it remains off by default (SAW-12484, #197).
- Deployment: B33 a5 moved staging to PostgreSQL HA; the follow-up HA image pin includes Revoke and the merged server fixes. Installing this CLI release does not perform those deployments (SAW-12484, #167, #168; SAW-12757, #194).
- Relay: prove the exact loopback listener with a per-listener private HMAC key before status, enable, activation, or pinned launch. Route state is rechecked under the relay lock, unsafe identity state fails closed, and direct disable remains available for rollback (SAW-12569, #200).
- Relay: keep the proof bounded to the control plane. It does not authenticate later bearer connections or proof-forwarding proxies.

Rollout: upgraded clients refuse an old relay. Restart each relay on the new binary before starting new managed launches. On macOS, upgrade the binary and restart `ai.sawmills.codexctl-relay` before routing. This release does not restart hosts or enable relay routes.

Installing this release does not deploy the account server or enable automatic account/model fallback, billed overflow, or reset redemption.
