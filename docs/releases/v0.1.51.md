# v0.1.51

- Client: opt in to a host-local relay for activated, pinned and automatic account-server launches. Capacity failures before and after output receive retry advice that Codex can honor on the same account and model. The relay does not replay requests; configured client retry counts remain unchanged (SAW-12569, #195).
- Relay: preserve active POST retry budgets through overlapping responses and cancellation. Keep seven UTC days of bounded, sanitized capacity metadata, with idle expiry and crash-tail recovery. Retain no prompts, output, tool data or tokens (#195).
- Server: stop forcing refreshes of valid tokens, recover unmarked owner-read failures and count account recovery failures (SAW-12766, #182, #183, #184).
- Dashboard: share read-only sessions across PostgreSQL pods and add guarded, audited Revoke with bounded connection waits. Restore owner and usage alert guidance (SAW-12757, #177, #187; SAW-12974, #192).
- Storage: fail closed on conflicting backfill rows, bound preflight scans and scope machine parity to the selected accounts (SAW-12484, #190, #191).

HQ owns the post-release Mac relay routing check after the normal Homebrew update. Devbox fake-upstream tests prove capacity retry behavior; the healthy live subscription turn proves routing. See [the relay guide](../relay.md).

Installing this release does not deploy the account server or perform the PostgreSQL cutover. Those operations need separate authorization. No automatic account/model fallback or billed overflow is introduced.
