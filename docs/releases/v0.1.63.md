# v0.1.63

GitHub did not publish v0.1.62 because the `macos-14` runner was no longer
available for Arm64. This release carries all v0.1.62 changes and moves the
`Darwin_arm64` release build to `macos-15` (FLT-1614, #268).

- If you omit `--model`, `codexctl-central run` defaults to `gpt-6.2-sol`.
  The relay counts that model for capacity accounting. `gpt-6.1-sol` stays in
  the allowlist so stored evidence keeps its model attribution (FLT-1614, #264).
- Dependency updates clear the OSV Scanner findings. Documented exceptions
  for the Chrono maintenance notice and `RUSTSEC-2023-0071` for `openidconnect`
  remain (SAW-13160, #261 and FLT-1614, #265).
- Staging can start the account server and scrape its metrics without the
  retired metrics credential file (SAW-13160, #259, #260).
- The README is simpler, obsolete files are gone, and the test fixture uses the
  correct backfill clock (FLT-544, #262 and SAW-13160, #263).

Roll out the account server first. A v0.1.61 account server rejects `gpt-6.2-sol`
on `/v1/capacity/plan` with HTTP 400 `invalid_capacity_plan`, which stops the
launch. Use an account-server image built from v0.1.62 source or later before
upgrading clients or relays to v0.1.63. No database migration is needed.
Installing the release does not restart a lane or relay. HQ owns machine
upgrades and relay restarts.
