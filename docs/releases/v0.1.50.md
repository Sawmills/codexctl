# v0.1.50

- Client: remove the rapid-rerun refresh trigger from `central-token`. Both helper forms request OAuth rotation only when the saved, revision-matched access-token expiry is less than one hour away (SAW-12766, part 3).
- Client: a rerun after HTTP 401 fetches the current shared revision without forcing another rotation. Stop reading or writing parent call history; legacy timing files are ignored. Keep private expiry hints and released connection compatibility.
- Regression proof: one client rotates and another receives that revision with no extra rotations. Ten parent processes each rerun three times without forcing, for both helper forms.

A 401 alone does not force an OAuth rotation. The guide owns client rollout. This hotfix needs no account-server deployment. See [the account server guide](../central-server.md).
