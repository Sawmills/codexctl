# Domain docs

This repo uses a single context: root `CONTEXT.md` and `docs/adr/` for architecture decision records (ADRs).

## Before exploration

Read root `CONTEXT.md` and any ADRs relevant to the task.
If these files do not exist, continue without warning or creating placeholders.
The `domain-modeling` skill creates them when the team resolves terms or decisions.

## Vocabulary and decisions

Use the glossary terms from `CONTEXT.md` in issue titles, proposals, tests, and hypotheses.
If a needed concept is absent, check whether the code already names it before proposing a new term.
If a proposal conflicts with an ADR, identify the ADR and explain the conflict rather than silently overriding it.

Edit this file if the repository later needs multiple contexts.
